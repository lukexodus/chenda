# Database Seeds

This directory contains seed data for the Chenda database.

## Overview

Seed files populate the database with initial data for development and testing:
- **~180 USDA Product Types** — Real perishable food data from FoodKeeper database
- **23 Philippine Regional Product Types** — Local specialties (Migration 009)
- **Custom Product Types** — Created at runtime by sellers; not seeded
- **10 Mock Users** — Test buyer and seller accounts
- **30+ Mock Products** — Sample product listings
- **Product Images** — Optional; fetched via `fetch-product-images.js`, applied by `seed.js`

## Files

```
seeds/
├── generate-seeds.js               # Converts JSON to SQL
├── seed.js                         # Main seeding CLI (safe/force/products-only)
├── clear-products.js               # Helper to clear orders+products only
├── fetch-product-images.js         # Downloads product type images via DuckDuckGo
├── product_types.sql               # ~180 USDA product types (auto-generated)
├── philippines_regional_products.sql   # 23 regional product types (Migration 009)
├── mock_users.sql                  # 10 test users
├── mock_products.sql               # 30 test products
├── nationwide_products.sql         # Additional nationwide sellers/products
├── products-list-unique.txt        # USDA product names — input for image fetcher
├── regional-products-list.txt      # Regional product names — input for image fetcher
└── product-images-manifest.json    # Generated by fetch-product-images.js; consumed by seed.js
```

## Seeding Modes

The seeder supports three modes:

| Mode | Command | What it does | When to use |
|---|---|---|---|
| Safe default | `node seed.js` | Seeds only if target tables are empty | First-time setup on a fresh DB |
| Full reset | `node seed.js --force` | Truncates `products`, `users`, `product_types` (cascade), then reseeds all files | Rebuild complete test dataset |
| Products only | `node seed.js --products-only` | Deletes `orders` then `products`, resets `products_id_seq`, reseeds product files only | Refresh listings while keeping users/types |

Additional utility:

| Utility | Command | What it does |
|---|---|---|
| Dry-run clear check | `node clear-products.js` | Shows counts, no writes |
| Confirm clear | `node clear-products.js --confirm` | Deletes `orders` + `products`, resets `products_id_seq` |

## What's New

### Migration 010 — Extensible Custom Product Types

Sellers can now create products that are **not in the catalog**. The system supports three tiers:

| Source | How created | Shelf life authority | ID range |
|---|---|---|---|
| `usda` | Seeded from FoodKeeper | Fixed research baseline | 1–9999 |
| `regional` | `philippines_regional_products.sql` | Community avg when ≥3 sellers override | 10001–19999 |
| `custom` | Runtime — seller API/form | Seller-provided; community avg over time | ≥10000 (sequence) |

Key changes:
- `source` CHECK constraint extended to include `'custom'`
- `community_avg_shelf_life_days` column — auto-updated by DB trigger
- Case-insensitive deduplication — same product name = same `product_types` row
- `products_enriched` view priority: seller override → community avg → original default

### Migration 011 — Product Type Images

`product_types` now has `image_url TEXT` (nullable):
- Populated by `seed.js` from `product-images-manifest.json` after seeding
- Shown as thumbnails in the product-type picker combobox
- Pre-fills listing image when seller selects a catalog type
- Custom types get `NULL`; sellers upload their own photo

### Migration 009 — Hybrid Product Types (baseline)

- USDA + Regional product type model
- `source` and `region` columns on `product_types`
- `product_shelf_life_overrides` table for per-seller customization

**See [HYBRID_PRODUCT_TYPES_SYSTEM.md](../HYBRID_PRODUCT_TYPES_SYSTEM.md) for API documentation and shelf life override usage.**

## Usage

### Generate Seed Files

Convert JSON data from algorithm to SQL:

```bash
node generate-seeds.js
```

This reads from:
- `chenda-algo/src/product-management/product-types.json` (180 USDA items)
- `chenda-algo/src/data/mock_users.json` (10 users)
- `chenda-algo/src/data/mock_products.json` (30 products)

**Note:** `philippines_regional_products.sql` is **not** auto-generated; it's a static file maintained in this directory. To add more regional product types, edit it directly or recreate it with the regional product template.

### Seed the Database

**Recommended full workflow (first time):**

```bash
# 1. Apply all pending migrations (009, 010, 011)
node migrations/migrate.js up

# 2. Download product images (optional but recommended)
node seeds/fetch-product-images.js --download --all

# 3. Seed — images are applied automatically at the end
node seeds/seed.js
```

**Re-seed everything** (clear and reload):
```bash
node seeds/seed.js --force
```

**Re-seed products only** (keeps users and product types):
```bash
node seeds/seed.js --products-only
```

**Help**:
```bash
node seeds/seed.js --help
```

## Product Images

Product type images are fetched once via DuckDuckGo Image Search (no API key) and stored locally in `public/images/products/`. `seed.js` reads the manifest and bulk-updates `product_types.image_url`, then propagates images to products.

### Image list files

| File | Source | Count |
|---|---|---|
| `products-list-unique.txt` | USDA catalog names | 474 |
| `regional-products-list.txt` | Philippine regional names | 23 |

Custom product types are created at runtime by sellers and **cannot be pre-fetched**. Sellers upload their own photos.

### Fetch commands

```bash
# USDA only (default, 474 items)
node seeds/fetch-product-images.js --download

# Regional only
node seeds/fetch-product-images.js --download --regional

# Both USDA + regional (full catalog)
node seeds/fetch-product-images.js --download --all

# Limit to N entries (fast test)
node seeds/fetch-product-images.js --download --all --limit 20

# Force re-download existing files
node seeds/fetch-product-images.js --download --all --force

# Dry run (no download, just shows what would happen)
node seeds/fetch-product-images.js --all
```

### Skip logic

The script checks for existing files across all common extensions (`.jpg`, `.webp`, `.png`, etc.) before downloading. Already-downloaded images are skipped unless `--force` is used.

### How seed.js integrates images

`seed.js` calls `applyImageManifest()` automatically after all SQL files run:
1. Reads `seeds/product-images-manifest.json`
2. `UPDATE product_types SET image_url = $path WHERE LOWER(name) = LOWER($name)` for each resolved entry
3. `UPDATE products SET image_url = pt.image_url` for products with no seller-uploaded image

If the manifest file doesn't exist, seeding continues with a warning — no error.


## Docker Compose Context

For Docker Compose deployment, seed after containers are up and migrations are applied.

1) Start containers:

```bash
docker compose up -d --build
```

2) Run migrations (required first).

3) Choose one seeding approach:

Option A: Pipe SQL files directly into the DB container

```bash
docker compose exec -T db psql -U postgres -d chenda < seeds/product_types.sql
docker compose exec -T db psql -U postgres -d chenda < seeds/mock_users.sql
docker compose exec -T db psql -U postgres -d chenda < seeds/mock_products.sql
docker compose exec -T db psql -U postgres -d chenda < seeds/nationwide_products.sql
```

Option B: Run `seed.js` via a temporary backend container

```bash
docker compose run --rm \
  -v "$(pwd)":/workspace \
  -w /workspace/seeds \
  --entrypoint node \
  backend seed.js
```

For full reset in Docker:

```bash
docker compose run --rm \
  -v "$(pwd)":/workspace \
  -w /workspace/seeds \
  --entrypoint node \
  backend seed.js --force
```

## Data Structure

### Product Types (180 USDA + 23 Regional = 203 total)

#### USDA Product Types (180 items)

From USDA FoodKeeper database with:
- Product name and subtitle
- Category ID
- Keywords for search
- Default shelf life (in days)
- Default storage condition (pantry/refrigerated/frozen variants)
- Source data (min/max/metric from USDA)
- `source` = `'usda'`

Example:
```sql
INSERT INTO product_types VALUES (
  33,
  'Yogurt',
  NULL,
  7,
  'Yogurt',
  11,
  'refrigerated_opened',
  '{"min":1,"max":2,"metric":"Weeks"}'::jsonb,
  'usda',
  NULL,
  true
);
```

#### Philippine Regional Product Types (23 items) — NEW

From `philippines_regional_products.sql` with:
- Product name and subtitle
- Category ID
- Keywords for search
- Default shelf life adjusted for **tropical storage**
- Default storage condition
- Source data with regional notes
- `source` = `'regional'`
- `region` = region name (e.g., "Ilocos Norte", "Visayas")
- `is_available_in_philippines` = `true`

Example:
```sql
INSERT INTO product_types VALUES (
  301,
  'Ilocos Garlic',
  'white; bulbs or cloves',
  13,
  'garlic,ilocos,bulbs,cloves,white garlic',
  180,
  'pantry',
  '{"min":4,"max":6,"metric":"Months","note":"Tropical storage in Ilocos Norte"}'::jsonb,
  'regional',
  'Ilocos Norte',
  true
);
```

Regional types include:
- **Ilocos specialties** — Garlic, tobacco
- **Tropical fruits** — Mango, pineapple, calamansi, coconut, banana
- **Regional vegetables** — Kangkong, okra, ampalaya, talong, highland vegetables
- **Regional proteins** — Heritage chickens, native pork, tilapia, carabao milk
- **Specialty items** — Bagoong, salted fish, queso de bola, sweet potato

### Shelf Life Overrides (NEW — Migration 009)

Table: `product_shelf_life_overrides`

Allows sellers to customize shelf life for their products based on storage conditions.

Structure:
- `seller_id` — Which seller
- `product_type_id` — Which product type
- `override_shelf_life_days` — Custom shelf life in days
- `override_storage_condition` — Custom storage (optional)
- `reason` — Why the override (e.g., "Tropical storage conditions")
- Unique constraint: one override per seller per product type

Example:
```sql
INSERT INTO product_shelf_life_overrides (seller_id, product_type_id, override_shelf_life_days, reason)
VALUES (5, 21, 21, 'Tropical storage reduces shelf life; must consume sooner in heat');
```

When freshness is calculated, the algorithm checks for overrides and uses custom shelf life if found.

See [HYBRID_PRODUCT_TYPES_SYSTEM.md](../HYBRID_PRODUCT_TYPES_SYSTEM.md) for API endpoints to manage overrides.

## Seeding Process

The `seed.js` script:

1. **Checks migrations** — Ensures database schema is created (all 11 migrations)
2. **Checks existing data** — Prevents accidental data loss
3. **Executes SQL files** in order:
   - `product_types.sql` (~180 USDA items)
   - `philippines_regional_products.sql` (23 regional items)
   - `mock_users.sql` (10 users)
   - `mock_products.sql` (30 products)
   - `nationwide_products.sql` (additional dataset)
4. **Applies image manifest** — reads `product-images-manifest.json`, updates `product_types.image_url`, propagates to products
5. **Shows final counts** — Confirms data was inserted

Notes:
- Trigger/sequence handling is implemented inside the SQL files where needed.
- In `--products-only`, `orders` are deleted before `products` to satisfy FK constraints.

## Verification

After seeding, verify data:

```bash
# Count records
psql -U postgres -d chenda -c "
  SELECT 'product_types' as table, COUNT(*) FROM product_types
  UNION SELECT 'users', COUNT(*) FROM users
  UNION SELECT 'products', COUNT(*) FROM products;
"

# Product type breakdown (USDA / Regional / Custom)
psql -U postgres -d chenda -c "
  SELECT source, COUNT(*) FROM product_types GROUP BY source ORDER BY source;
"
# Expected: usda | ~180, regional | 23, custom | 0 (grows as sellers add products)

# Image population check
psql -U postgres -d chenda -c "
  SELECT
    COUNT(*) FILTER (WHERE image_url IS NOT NULL) AS types_with_images,
    COUNT(*) AS total_types
  FROM product_types;
"
psql -U postgres -d chenda -c "
  SELECT
    COUNT(*) FILTER (WHERE image_url IS NOT NULL) AS products_with_images,
    COUNT(*) AS total_products
  FROM products;
"

# Check community avg trigger (after 3+ overrides on same type)
psql -U postgres -d chenda -c "
  SELECT name, community_avg_shelf_life_days, community_override_count
  FROM product_types
  WHERE community_override_count >= 3
  LIMIT 5;
"

# Check shelf life overrides table exists (Migration 009)
psql -U postgres -d chenda -c "\dt product_shelf_life_overrides"

# Check products with enriched shelf life (via products_enriched view)
psql -U postgres -d chenda -c "
  SELECT p.id, pt.name, pt.source,
    p.effective_shelf_life_days,
    p.shelf_life_source
  FROM products_enriched p
  JOIN product_types pt ON pt.id = p.product_type_id
  LIMIT 5;
"
```
